## 实验 3-5：BM25 稀疏检索与 RAG（本人运行）

### 运行说明

项目：`chapter3/sparse-embedding`

### 实验目的

理解 RAG 中最基础的检索环节：BM25 如何用倒排索引 + TF/IDF 打分，从语料中找出与查询相关的文档。

### 实验结果

#### 1. 检索质量评测（默认参数 k1=1.5, b=0.75）

| 查询 | recall@5 | precision@5 | 备注 |
| --- | ---: | ---: | --- |
| model distillation | 1.00 | 1.00 | 正常召回 |
| HTTP 404 error | 1.00 | 0.50 | 召回正确，但混入无关文档 |
| XK9-2B4-7Q1 | 1.00 | 1.00 | 编号精确匹配 |
| BM25 ranking function | 1.00 | 1.00 | 正常召回 |
| cat | 0.00 | 0.00 | **完全漏召回** |

宏平均：

```text
recall@5 = 0.800
precision@5 = 0.700
MRR = 0.800
```

#### 2. 单条查询 + 逐词打分（model distillation）

| 排名 | 文档 | 分数 | 命中词 |
| --- | --- | ---: | --- |
| 1 | doc_3 Model Distillation | 3.1216 | model, distillation |
| 2 | doc_4 Knowledge Distillation | 2.2197 | model, distillation |

逐词贡献示例（doc_3）：

```text
'model':        TF=3, 文档长度=13词, IDF=1.2238, BM25贡献=1.9705
'distillation': TF=1, 文档长度=13词, IDF=1.2238, BM25贡献=1.1511
```

这说明：TF 越高、词越稀有（IDF 越高），对排序贡献越大。

#### 3. 扩展：修改 BM25 参数对比

| 参数 | doc_3 分数 | doc_4 分数 | 分数差 |
| --- | ---: | ---: | ---: |
| 默认 k1=1.5, b=0.75 | 3.1216 | 2.2197 | 0.9019 |
| k1=2.0, b=0.5 | 3.3117 | 2.2746 | 1.0371 |
| k1=1.0, b=0.0 | 3.0594 | 2.4476 | 0.6118 |

参数含义与观察：

- **k1（词频饱和）**：调大后，高词频文档得分更高，分数差拉开
- **b（文档长度归一化）**：调小后，长短文档差异被弱化，doc_4（更长）相对追近
- **b=0**：完全不做长度归一化，长文档不再被惩罚

评测指标层面：在这套小语料上，改参数没有改变 recall@5（仍为 0.800），因为「cat」的失败来自**同义词缺失**，不是排序参数问题。

#### 4. 同义词短板（cat）

查询 `cat`，相关文档是 doc_7 / doc_8（讲 kitten / feline），但 BM25 完全命中不了：

```text
没有命中任何文档（所有查询词都不在倒排索引中）。
```

这是**词法匹配**检索的根本局限：查询词和文档词没有字面重叠，就召回不了。

### 短期上下文 vs 长期记忆 vs RAG

| 概念 | 存在哪里 | 生命周期 | 本次实验对应 |
| --- | --- | --- | --- |
| **短期上下文** | 每次 LLM 调用的消息列表 | 当前会话内 | Task1 实验 2-9 状态栏 |
| **长期记忆** | 跨会话存储（用户偏好、历史事实） | 持久化 | 本章 user-memory |
| **RAG 知识库** | 外部文档库 / 向量索引 | 持久化，按需检索 | 本实验 3-5 BM25 |

一句话关系：

```text
短期上下文 = 这次模型「看得见」的信息
长期记忆  = 跨会话「记得住」的信息
RAG       = 从外部知识库「捞回来」再塞进上下文的信息
```

### 结论

1. **RAG 的检索层**负责「从知识库里捞出和问题相关的片段」，BM25 是最经典的稀疏检索方法。
2. BM25 基于词面匹配（TF/IDF/文档长度），**能解释、能调参、速度快**。
3. 参数 k1 / b 会改变分数和排序，但解决不了**语义鸿沟**（同义词、近义表达）。
4. 这正是后续需要**稠密向量检索 / 混合检索 / 重排序**的原因。

### 一句话总结

> RAG 是把外部知识「捞进上下文」的管道；检索质量直接决定 Agent 能否基于正确知识作答。
