## 实验 5-5：代码化规则守卫（本人运行）

### 运行说明

项目：`chapter5/small-model-codified-rules`  
运行方式：`python demo.py --selftest`（完全离线，不调用 API）  
运行时间：2026-09-22  
证据目录：`Task4 Coding Agent 与通用 Agent/实验5-5执行结果/codified-rules`

### 实验目的

理解 Coding Agent 生产场景中的核心安全问题：

> **模型说「可以退」就真的可以退吗？**

本实验证明：**不能只信模型自报，必须有服务端真值校验。**

### 实验结果

#### 实验设计

用 60 个退款用例（TB001 ~ TB060）做对照：

| 组 | 做法 | 结果 |
| --- | --- | --- |
| **控制组**（天真工具） | 只信模型自报，不校验 | 遇到「不可退」用例时违规退款 |
| **实验组**（代码化守卫） | 工具内嵌数据库真值校验 | 不可退一律拦截，可退才放行 |

#### 关键发现

**1. 控制组的违规**

TB009、TB012、TB013、TB016、TB017、TB020 等「不可退」用例：

```text
政策真值 is_refundable -> refundable=False
[控制组·天真工具] status=ok 退款=509.0  ← 违规！政策不可退却退了
```

**2. 实验组的拦截**

同样的用例：

```text
[实验组·代码化] 模型自报expected_refundable=True -> status=rejected [拒绝(policy_violation)] 退款=0.0
```

**3. 模型自报经常是错的**

自检中故意灌入与真值相反的自报值：

```text
自报=False vs 真值=True -> 不一致（已记录告警）
自报=True vs 真值=False -> 不一致（已记录告警）
```

无论模型自报什么，实验组一律以数据库真值裁决。

### 核心结论

```text
结论：无论模型自报什么，实验组一律以数据库真值裁决——
     不可退的一律被拦截，可退的才放行。
```

这正是 Harness 工程中 **验证（Verify）** 机制的典型例子：

| 机制 | 作用 | 本实验对应 |
| --- | --- | --- |
| **约束** | 设定行为边界 | 退款政策规则 |
| **验证** | 自动判断操作对错 | 服务端真值校验 |
| **纠正** | 发现问题时修正/拦截 | 拒绝违规退款 |

### 一句话总结

> 生产级 Coding Agent 的关键不是「模型有多聪明」，而是「模型之外有没有可靠的验证与约束」。模型声明可以参考，但最终裁决必须来自服务端真值。
