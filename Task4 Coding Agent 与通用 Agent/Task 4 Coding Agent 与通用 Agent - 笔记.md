### Coding Agent 的核心循环是什么？

Coding Agent 的工作流程可以概括为：

```text
读/搜（理解需求）→ 补丁（写代码）→ 测试（验证）→ 修复（改错）→ 验收（确认完成）
```

这个循环的关键特征是：**模型声明**与**环境事实**被分开验收。

- **模型声明**：Agent 说「我已经修好了」「退款金额是 501」
- **环境事实**：测试是否真的通过？数据库里的金额是否正确？

生产级 Agent 绝不能只信模型的自我报告。


### 为什么需要「代码化规则守卫」？

核心问题：

> Agent（LLM）的判断可能出错，但业务规则必须准确执行。

举例：航空退款场景

| 舱位 | 下单时间 | 航班状态 | 是否可退 |
| --- | --- | --- | --- |
| basic_economy | 24h 内 | scheduled | ✅ |
| basic_economy | 24h 外 | scheduled | ❌ |
| basic_economy | 任何 | cancelled_by_airline | ✅ |
| economy_flex | 任何 | 任何 | ✅ |

这些规则如果只写在提示词里，模型可能记错、漏看、被注入攻击绕过。

**代码化规则守卫**的做法是：

1. 把规则写成**代码**（而非自然语言）
2. 在**工具执行层**嵌入真值校验
3. 模型的自报值只做参考，最终裁决来自数据库/规则引擎

实验 5-5 的结果证明：控制组在「不可退」用例上违规退款，实验组全部拦截。


### Harness 工程中的「约束 / 验证 / 纠正」

| 机制 | 职责 | 例子 |
| --- | --- | --- |
| **约束（Constrain）** | 设定行为边界 | 权限控制、金额上限、工具白名单 |
| **验证（Verify）** | 自动判断操作对错 | 服务端真值校验、测试执行、类型检查 |
| **纠正（Correct）** | 发现问题时修正/回退 | 拒绝违规操作、静默重试、熔断机制 |

实验 5-5 完整演示了这三层：

- **约束**：退款政策（basic_economy 超 24h 不可退）
- **验证**：工具内嵌真值校验，对比模型自报与数据库真值
- **纠正**：`status=rejected [拒绝(policy_violation)]`，退款=0


### 通用工具 vs 专用工具怎么选？

**默认取向：通用工具优于专用工具，除非存在明确的安全、权限或性能理由。**

适用专用工具的场景：

1. **安全、权限与审计**：生产数据库写操作需要精细权限控制
2. **屏蔽平台差异**：grep/find 在 Mac/Windows/Linux 上语法不同
3. **使用频率极高**：高频操作值得专属入口
4. **参数结构复杂**：嵌套对象、多字段联合校验

实验 5-5 的退款工具就是专用工具的典型例子：涉及资金安全，必须专用 + 服务端校验。
